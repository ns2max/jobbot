# jobbot — Central PM over career-ops + ai-job-search

This root directory holds two complete, independent job-search tools:

- **`career-ops/`** — broad-net evaluation engine. Zero-token portal scanner (45+ AI/tech companies via Greenhouse/Ashby/Lever APIs), A-F/A-G scoring, batch parallel evaluation, Go TUI dashboard, interview story bank, negotiation scripts, rejection-pattern analysis, follow-up cadence. Has its own `CLAUDE.md`/`AGENTS.md`.
- **`ai-job-search/`** — precision application pipeline, personalized to Nishal Silva (`ai-job-search/input/knowledge-graph.md` is the canonical profile). Drafter-reviewer `/apply` with mandatory PDF compile + ATS text-layer verification, Danish/local portal scrapers + LinkedIn/freehire, Gmail/Notion sync, outcome archive, per-application interview prep, upskill gap analysis. Has its own `CLAUDE.md`.

Both were built and used independently and already track overlapping jobs under a shared ID space (see `ai-job-search/job_scraper/id_counter.json` — career-ops is the ID authority). **Do not treat either as a subordinate module of the other** — each is a full system with its own onboarding, data contract, and conventions. This root layer only routes between them and reconciles their state.

## First thing to do each session

Read and follow `.claude/skills/pipeline-pm/SKILL.md`. In short:

```bash
python3 tools/pipeline_status.py
```

then check `data/unified-tracker.md` for ID collisions and cross-tool duplicates before doing anything else pipeline-related. Use `/pipeline-status` to re-run this on demand.

## Routing a task

- Job URL/JD pasted with no tool named → check the unified tracker for an existing entry first; if new, evaluate wherever makes sense but **always finish actual CV/cover-letter drafting in `ai-job-search`'s `/apply`** (its PDF/ATS verification loop has no equivalent in career-ops).
- "Do a job search" / "find me jobs" → `/job-search`: run **both** tools' discovery, score both queues, merge, and present **one** results section — never two separate per-tool write-ups. Full sequence in `.claude/skills/pipeline-pm/SKILL.md`.
- "What should I do next" / status questions → `/pipeline-status`, then career-ops `patterns`/`followup` and ai-job-search `/outcome followup` for anything the merge flagged as stale.
- Full routing table (discovery, triage, drafting, interview prep, negotiation, outcomes, upskilling, dashboards) is in `.claude/skills/pipeline-pm/SKILL.md`.

## Numbering and duplicates

There is **one job-ID space** across both tools. career-ops is the authority: when the same real-world job is tracked by both tools under different IDs, the career-ops ID is canonical.

- `tools/pipeline_status.py` collapses duplicate roles (company similarity > 0.85 AND role similarity > 0.75) into one row per job in `data/unified-tracker.md`/`.json` — this is the single source of truth for "how many jobs are actually in the pipeline," not either tool's own tracker alone.
- New IDs assigned during a `/job-search` run come from the unified tracker's `next_safe_id`, not from either tool's counter in isolation.
- Existing duplicates surface as `renumber_plan` entries. Fixing them (`--apply-renumber`) rewrites ai-job-search's tracker/`seen_jobs.json`/files — always show the plan and get explicit confirmation before running it, every time, regardless of standing policy.
- A same-ID-but-different-job collision is not a duplicate — it's a numbering accident. Flag it; it needs a fresh ID on the ai-job-search side, not a merge.

## Resumes and cover letters

`resumes/` and `cover-letters/` hold the one canonical copy of every above-threshold, not-yet-applied CV/cover-letter pair (career-ops score ≥4.0/5 evaluated, or ai-job-search fit_rating ≥80/100 drafted) — named `{canonical_id}_{company-slug}_{role-slug}.{ext}`. Run `python3 tools/unify_documents.py` after any new pair is generated to relocate it there; each tool still records what it did (career-ops gets a `[docs: unified]` tag in its Notes column, ai-job-search's `cv_file`/`cover_letter_file` columns get rewritten to the new path) — the move doesn't erase either tool's own history, it just leaves one copy of the actual files. Full rule in `.claude/skills/pipeline-pm/SKILL.md`.

## Rules

- Never edit either tool's system-layer files (`career-ops/modes/_shared.md`, `ai-job-search/.claude/skills/*`) from this root role — customization requests for a specific tool go through that tool's own CLAUDE.md rules.
- `data/unified-tracker.md` and `.json` are generated by `tools/pipeline_status.py` — never hand-edit, just re-run.
- Neither tool auto-submits applications; this layer doesn't override that. All final submits are the user's call.
