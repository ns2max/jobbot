## Modification plan for #1 (Life360)

Per the standing minor-tailoring rule — reordering/light extension only, nothing fabricated, and an honest flag on what tailoring *cannot* fix:

- **Tagline:** swap to the embedded/edge framing already used for 619/624/626: *"Machine Learning Research Engineer | Embedded & Real-Time Inference, Signal Processing, Edge AI | Applied ML"* — directly matches the JD's "Edge ML" framing.
- **Technical Stack, Languages line:** currently reads *"Python, C++, C, JavaScript, MATLAB, C#"* — reorder (not reword) to lead with C++ and C, since those are the JD's primary languages, ahead of Python: *"C++, C, Python, JavaScript, MATLAB, C#"*. Same list, same words, different order.
- **MAS Holdings bullet:** the existing line *"Developed ML-driven optimization and decision engines to support real-time monitoring and long-term capacity/efficiency planning from streaming machine and sensor data"* and the existing *"Built real-time data ingestion and ETL pipelines for high-frequency IoT and operational time-series data across distributed sites"* are the closest true content to "embedded sensor data processing on-device" — no wording change needed, they already say this; just don't bury them.
- **What tailoring cannot do:** the JD's core requirements — RTOS internals, low-level driver development, hardware debugging tools (JTAG/scope/logic analyzer), "10+ years of firmware engineering" as the primary discipline — are not present anywhere in the resume and there is no truthful way to surface them, because the candidate's embedded experience is ML-deployment-on-embedded-hardware, not firmware/driver engineering. **Recommend the user decide explicitly** whether to apply understanding this gap will likely surface hard in a technical interview, rather than treating this as a "perfect fit" the way #619 (Samsara Edge AI) or #626 (Liquid AI) were.
