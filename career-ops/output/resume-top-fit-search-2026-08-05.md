## Methodology

This project already has 600+ prior evaluations (`data/pipeline.md`) and 60+ tracked applications (`data/applications.md`) going back to 2026-04-08, most recently 2026-07-09. Rather than re-running a full search from scratch, I: (1) mined the existing `Processed` history for roles scored ≥3.7/5 that were **never marked Applied/Rejected/Discarded** — proven high-fit matches the pipeline already found but the user never acted on; (2) reviewed the 53 postings just added by `node scan.mjs` (pulled live from company ATS APIs seconds before this search, so liveness is inherent) plus the pre-existing 98 unevaluated `Pending` items for anything matching the resume's real strengths (audio/speech, signal processing/DSP, time-series, embedded/edge ML, industrial CV, IoT); (3) spot-verified liveness on the top ~10 candidates via WebFetch (no browser tool available in this session — Playwright-based verification per project policy is not possible here; treated as the documented batch-mode fallback). Two broad WebSearches for "new since 2026-07-09" postings returned only generic aggregator noise (Glassdoor/Indeed listing pages, not individual postings) — nothing usable beyond what the ATS-based scan already surfaced.

The resume's tagline is *"Machine Learning Research Engineer | Deep Learning, Time-Series, Pattern Detection | Applied ML"*. Its body already contains: real-time inference (<30ms, >90% F1), time-series/anomaly detection, computer vision at industrial scale (300% throughput, MAS Holdings), signal processing/DSP, C++/Python, and audio/music research (JAES 2026, DAFx 2022, MUSMET postdoc). It does **not** explicitly say "embedded" or "edge" anywhere — a minor keyword gap for roles titled that way.
